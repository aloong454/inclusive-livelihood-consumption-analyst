# 课程项目评估量表

> 总分 100 分。用于小组自评、互评和答辩准备。每个维度给出“合格/良好/优秀”的行为描述。

## 1. 问题与用户（15 分）

| 等级 | 表现 |
|---|---|
| 合格（9—11） | 说清题目背景，但用户和场景比较泛 |
| 良好（12—13） | 明确目标用户、使用场景和现有痛点 |
| 优秀（14—15） | 用户具体、场景可验证、边界清楚，能说明“为什么不是另一个产品” |

**检查：**

- [ ] 目标用户是谁？
- [ ] 他们在什么场景下使用？
- [ ] 现有做法为什么不够？
- [ ] 你们不做什么？

## 2. 数据与指标（20 分）

| 等级 | 表现 |
|---|---|
| 合格（12—14） | 有数据来源，能算基本占比和增速 |
| 良好（15—17） | 口径清楚，有对比基准，能处理同比/环比 |
| 优秀（18—20） | 有数据体检、样本量说明、局限分析，能识别口径陷阱 |

**检查：**

- [ ] 数据来源、时间、样本量？
- [ ] 名义/实际、同比/环比？
- [ ] 总计与分项是否对得上？
- [ ] 是否区分真实数据与模拟数据？
- [ ] 是否说明样本偏差？

## 3. AI/技术方案（20 分）

| 等级 | 表现 |
|---|---|
| 合格（12—14） | 能调用模型完成问答/总结 |
| 良好（15—17） | 有 RAG、工具调用、结构化输出或工作流 |
| 优秀（18—20） | 有可复用的 SKILL、可复现脚本、评估与失败案例分析 |

**检查：**

- [ ] AI 具体做了什么，不是“套壳”？
- [ ] 是否有工具调用/计算/检索？
- [ ] 输出是否结构化、可追溯？
- [ ] 是否有失败案例和改进？
- [ ] 换一个城市/群体还能用吗？

## 4. 洞察与表达（20 分）

| 等级 | 表现 |
|---|---|
| 合格（12—14） | 能描述数据，但结论比较表面 |
| 良好（15—17） | 有“发现—证据—含义”，有对比和解释 |
| 优秀（18—20） | 有反直觉发现，能区分相关与因果，建议可执行 |

**检查：**

- [ ] 一句话结论是什么？
- [ ] 每个结论有证据吗？
- [ ] 是否解释了“为什么”？
- [ ] 是否给出可执行建议？
- [ ] 是否主动说出局限？

## 4.1 图表检查（单独 10 分，可从“洞察与表达”中拆出）

- [ ] 饼图只用于 part-to-whole，类别 ≤7；
- [ ] 柱形图用于年龄组/城市比较，纵轴从 0 开始；
- [ ] 年龄组按自然顺序，不按数值大小打乱；
- [ ] 每张图写清分母（全市总消费/该年龄组总消费）；
- [ ] 有标题、副标题（口径）、数值标签、来源、模拟/真实标注；
- [ ] 没有 3D、阴影、渐变堆叠；
- [ ] 没有用多张饼图比较多个年龄组；
- [ ] 图表结论与正文数字一致。

## 5. 伦理与合规（15 分）

| 等级 | 表现 |
|---|---|
| 合格（9—11） | 提到隐私/伦理，但比较空泛 |
| 良好（12—13） | 有具体红线、脱敏、人工复核 |
| 优秀（14—15） | 有公平性检查、反诱导借贷、申诉/纠错机制，能回答红队问题 |

**检查：**

- [ ] 是否做个人授信决策？
- [ ] 是否推断敏感属性？
- [ ] 是否诱导过度借贷？
- [ ] 是否有数据最小化/脱敏？
- [ ] 是否有人工复核与纠错渠道？

## 6. 展示与答辩（10 分）

| 等级 | 表现 |
|---|---|
| 合格（6—7） | 能讲完，但超时/照读 |
| 良好（8—9） | 节奏清楚，图表可读，分工明确 |
| 优秀（10） | 故事线强，Demo 稳，答辩能承认不知道 |

**检查：**

- [ ] 8 分钟内讲完？
- [ ] 每页一个观点？
- [ ] 图表有标题、单位、来源？
- [ ] Demo 有备份（录屏/截图）？
- [ ] 每位成员都能回答自己负责的部分？

## 7. 加分项（最多 10 分，不突破 100）

- 可复用的 SKILL/开源仓库；
- 真实用户访谈或可用性测试；
- 公平性/偏见评估；
- 失败案例与迭代记录；
- 现场 Demo 稳定，能处理追问。

## 8. 扣分项

- 把模拟数据说成真实数据（−10）；
- 给出个人授信结论（−10）；
- 诱导过度借贷（−10）；
- 数据来源不明/无法复核（−5）；
- 超时严重（−5）；
- 全员只由一人回答（−3）。

## 9. 答辩前 10 分钟自检

- [ ] 一句话能说清“我们做了什么”；
- [ ] 一个数字能支撑核心结论；
- [ ] 一个 Demo 能跑通；
- [ ] 一条边界能说清；
- [ ] 一个失败案例能讲；
- [ ] 一个下一步能说；
- [ ] PPT 有备份；
- [ ] 数据有来源；
- [ ] 代码有 README；
- [ ] 全组知道彼此负责的部分。
