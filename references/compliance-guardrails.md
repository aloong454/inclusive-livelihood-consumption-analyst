# 合规与责任边界

> 这不是法律意见。正式对外使用前，必须由所在机构的合规、法务和消费者权益保护部门复核。

## 1. 五条红线

### 红线 1：不做个人授信决策

不得输出：

- “这个人可以批 5 万元”；
- “建议通过/拒绝该客户”；
- “该客户风险等级为 A”；
- “建议利率 7.2%”；
- “可以提额到 10 万元”。

可以输出：

- 群体层面的消费结构、需求特征和场景洞察；
- 产品设计的假设与待验证问题；
- “需结合偿付能力、征信、反欺诈和适当性评估后，由人工复核”。

### 红线 2：不推断敏感属性

不得基于姓名、地址、消费记录、设备信息等推断：

- 民族、宗教、政治倾向；
- 健康状况、残障、疾病；
- 性取向、婚姻/生育状况；
- 其他受法律保护的个人信息。

不得使用“代理变量”绕开限制。例如，用“某类药品购买”推断疾病，用“某地区”推断民族。

### 红线 3：不诱导过度借贷

禁止：

- “额度不用白不用”；
- “秒批、必过、零门槛”；
- “先消费，后还款，毫无压力”；
- 针对收入不稳定、负债较高、金融素养不足人群的紧迫式营销；
- 把“消费升级”直接等同于“应该借钱”。

必须：

- 展示年化利率/综合资金成本（如适用）；
- 提示逾期后果与征信影响；
- 提供“不借款/少借款”的选择；
- 对明显超出还款能力的场景设置人工复核。

### 红线 4：数据最小化与去标识化

- 只收集完成分析所必需的数据；
- 分析前删除姓名、身份证号、手机号、银行卡号、精确住址；
- 小样本分组（如少于 30 人）不做单独披露，防止反推个人；
- 不把个人数据粘贴到未经批准的第三方模型/工具；
- 日志中不记录原始个人数据。

### 红线 5：可解释、可复核、可申诉

- 每个结论都要能回到数据、公式和口径；
- 每个建议都要标注“需人工复核”；
- 保留分析过程、版本和假设；
- 对外产品应提供申诉/纠错渠道；
- 不用“AI 说的”作为最终理由。

## 2. 普惠金融“适当性”检查

在把洞察转化为产品建议前，逐项确认：

| 维度 | 要问的问题 | 输出要求 |
|---|---|---|
| 目的适当 | 这个产品解决什么真实需求？ | 写明场景，不写“泛化提额” |
| 对象适当 | 目标客群是否理解产品？ | 避免向金融素养不足人群推销复杂结构 |
| 能力适当 | 客户是否有稳定还款来源？ | 需结合收入、负债、现金流，不能只看消费 |
| 期限适当 | 借款期限与需求周期是否匹配？ | 短需求不配长期高成本资金 |
| 价格适当 | 综合成本是否透明、可承受？ | 明确年化利率与全部费用 |
| 信息适当 | 是否充分披露风险？ | 不隐藏逾期、征信、提前还款条款 |
| 渠道适当 | 是否存在诱导、捆绑、默认勾选？ | 默认关闭，明确选择 |
| 救济适当 | 是否有投诉与纠错渠道？ | 提供人工入口 |

## 3. 偏见检查

### 3.1 数据偏见

- 样本是否只覆盖“已经获得金融服务的人”？（幸存者偏差）
- 是否忽略了没有银行卡、没有稳定工作、没有信用记录的人？
- 线上数据是否偏向年轻、城市、高学历群体？
- 地区数据是否把“低消费”误读为“低需求”？

### 3.2 标签偏见

- 是否把“消费少”标成“低价值客户”？
- 是否把“借款多”标成“高需求”？
- 是否把“频繁退货/比价”标成“高风险”？
- 标签是否带有道德判断？

### 3.3 代理变量偏见

即使不使用敏感属性，以下变量也可能成为代理：

- 邮编/小区；
- 手机品牌/机型；
- 教育经历；
- 职业类型；
- 消费品牌；
- 方言/语言。

使用前必须做公平性评估，并说明理由。

### 3.4 输出偏见

- 不用“优质/劣质客户”等人格化标签；
- 不用“下沉市场=低端”的叙事；
- 不把“新市民”描述成单一同质群体；
- 不把“消费升级”当成唯一正确方向。

## 4. 语言规范

### 4.1 推荐措辞

- “在……口径下”；
- “可能/倾向于/初步显示”；
- “需结合……进一步验证”；
- “建议评估/可考虑/需人工复核”；
- “本结论不构成授信建议”。

### 4.2 禁止措辞

- “保证/稳赚/零风险”；
- “一定能批/秒批/必过”；
- “所有人/必然/彻底证明”；
- “低端人群/劣质客户”；
- “不借就亏了/额度不用白不用”。

## 5. 典型风险场景与应对

### 场景 A：用户要求“给这个客户批多少额度”

**应对：**

> 我不能根据消费数据给出个人授信结论。可以帮你做该客户所属群体的消费结构分析，供人工结合收入、负债、征信和适当性评估参考。

### 场景 B：用户要求“找出最容易被营销的人群”

**应对：**

> 可以分析群体层面的需求场景和产品适配性，但不能针对脆弱人群做诱导性营销。建议先做适当性与公平性评估。

### 场景 C：数据里只有“消费高/低”，没有收入

**应对：**

> 消费高不等于还款能力强。缺少收入、负债和现金流数据时，不能推断偿付能力，只能做描述性分析。

### 场景 D：模型结论与业务直觉冲突

**应对：**

1. 回查数据与口径；
2. 检查样本结构；
3. 检查基期与异常值；
4. 并列展示两种解释；
5. 不为了“讲得通”而修改数据。

### 场景 E：对外发布/媒体引用

**应对：**

- 标明数据来源、时间、口径、样本量；
- 避免把模拟数据写成真实统计；
- 避免用单个案例代表整体；
- 由机构合规/公关审核后再发布。

## 6. 全球/跨境场景

### 6.1 司法辖区优先

同一个“消费贷”产品，在不同国家可能适用完全不同的规则：

- 数据保护：GDPR（欧盟）、LGPD（巴西）、CCPA/CPRA（美国加州）及各国本地法；
- 消费者保护：利率上限、费用披露、冷静期、催收规范；
- 征信：credit bureau / credit registry 的覆盖与授权；
- 数字金融：移动钱包、代理银行、电子签名、跨境支付；
- 文化与宗教：伊斯兰金融的利息/费用结构；
- 制裁与反洗钱：跨境资金流动的合规审查。

**规则：** 不要用一国的“适当性”标准直接判断另一国产品；全球报告必须写明适用司法辖区，并提示当地合规复核。

### 6.2 跨境数据传输

- 确认数据是否可以出境；
- 使用脱敏/聚合数据，避免个人明细跨境；
- 如涉及欧盟/巴西等辖区，检查跨境传输机制（SCCs、 adequacy decision、DPA 等）；
- 不把个人数据粘贴到未经批准的第三方模型/工具。

### 6.3 跨境比较的伦理

- 不把不同国家的消费结构做成“文明/优劣”排名；
- 不把“消费低”写成“需求低”或“市场差”；
- 不忽略非正规经济、非正式租赁、家庭自产自用；
- 不把 PPP 比较结果用于个人授信或定价。

### 6.4 场景：用户要求“全球城市排名”

**应对：**

> 可以做结构/PPP 的描述性对比，但不能做“哪个城市更好/更差”的价值判断，也不能用排名推导个人信用或产品授信。需要先确认分类、币种、PPP、数据层级，并标注可比性等级。

### 6.5 场景：只有一国监管意见，要做另一国产品

**应对：**

> 一国合规意见不能直接套用到另一国。请提供目标国家的法律/监管意见，或先做描述性分析，由当地合规团队确认。

## 7. 交付前合规清单

- [ ] 没有个人授信、额度、利率、通过率结论；
- [ ] 没有敏感属性推断或代理歧视；
- [ ] 没有诱导过度借贷的文案；
- [ ] 数据已脱敏，小样本已合并/隐藏；
- [ ] 每个数字有来源和口径；
- [ ] 每条建议有“人工复核/合规确认”；
- [ ] 已写明局限与失败案例；
- [ ] 已提供纠错/申诉/人工入口；
- [ ] 对外使用前已由合规/法务复核；
- [ ] 全球模式：已写明适用司法辖区；
- [ ] 全球模式：已检查跨境数据传输；
- [ ] 全球模式：没有把一国规则套到另一国；
- [ ] 全球模式：没有做价值判断式的城市排名。
